# Model Card: Random Forest Network Flow Classifier

Following the framework proposed by [Mitchell et al. (2019)](https://arxiv.org/abs/1810.03993).

## 1. Model Details
- **Model Name:** Random Forest Network Flow Classifier
- **Model Version:** 0.1.0 (Baseline)
- **Model Type:** Supervised Ensemble Classifier (`sklearn.ensemble.RandomForestClassifier`)
- **Parameters:**
  - `n_estimators`: 100
  - `random_state`: 42
  - `criterion`: Gini impurity
  - `n_jobs`: -1
- **Target Task:** Multi-class classification of IP network flows (benign vs. attack classes).
- **License:** MIT

## 2. Intended Use
- **Primary Use Case:** Offline and batch analysis of reconstructed bidirectional IP network flows.
- **Out-of-Scope Use Cases:**
  - Unsupervised zero-day payload inspection (model expects statistical flow header features, not deep packet inspection).
  - Standalone automated blocking/firewall rules without human-in-the-loop verification.
  - Deployment in production networks without prior domain-specific fine-tuning or drift calibration.

## 3. Training Data
- **Dataset:** [CIC-IDS-2017](https://www.unb.ca/cic/datasets/ids-2017.html) (Canadian Institute for Cybersecurity).
- **Data Subsets Used:**
  - `Monday-WorkingHours.pcap_ISCX.csv` (Benign baseline)
  - `Tuesday-WorkingHours.pcap_ISCX.csv` (FTP-Patator, SSH-Patator)
  - `Wednesday-workingHours.pcap_ISCX.csv` (DoS / Heartbleed)
  - `Thursday-WorkingHours-Morning-WebAttacks.pcap_ISCX.csv` (Web Attacks)
  - `Thursday-WorkingHours-Afternoon-Infilteration.pcap_ISCX.csv` (Infiltration)
  - `Friday-WorkingHours-Morning.pcap_ISCX.csv` (Botnet)
  - `Friday-WorkingHours-Afternoon-PortScan.pcap_ISCX.csv` (PortScan)
  - `Friday-WorkingHours-Afternoon-DDos.pcap_ISCX.csv` (DDoS)
- **Input Dimensions:** 78 statistical flow features (duration, packet counts, inter-arrival times, flag counts, byte counts).

## 4. Preprocessing & Feature Pipeline
- **Whitespace Stripping:** Removes trailing and leading spaces in column headers.
- **Handling Non-finite Values:** Inf/-Inf mapped to NaN; rows containing NaNs or missing labels dropped.
- **Excluded Non-Feature Columns:** `Flow ID`, `Source IP`, `Destination IP`, `Timestamp`, `Label`.
- **Transformation:** `StandardScaler` applied to numeric columns.
- **Target Encoding:** `LabelEncoder` mapping strings to integer classes.

> ⚠️ **Known Flaw in Current Baseline (Phase 0):** `StandardScaler` was fitted globally across combined data prior to train/test partitioning. This introduces statistical leakage and will be resolved in Phase 1 via an `sklearn.pipeline.Pipeline` fitted strictly on training folds.

## 6. Limitations, Biases & Known Issues
1. **Dataset Flaws in CIC-IDS-2017:**
   - As documented by [Engelen et al. (2021)](https://doi.org/10.1016/j.cose.2021.102371), the original CIC-IDS-2017 dataset suffers from labeling errors, corrupted flow generation artifacts from early `CICFlowMeter` versions, and synthetic traffic generation artifacts.
2. **Feature Extractor Discrepancies:**
   - Features generated by offline `CICFlowMeter` versions often exhibit subtle mathematical drift when compared to real-time packet sniffers (`pcap`/`gopacket`). Phase 2 incorporates a golden-PCAP parity validation test.
3. **Generalization Gap:**
   - A model trained purely on CIC-IDS-2017 traffic will degrade significantly when exposed to modern campus or enterprise network flows. Domain adaptation and drift monitoring (PSI/KS tests) are required.
